# Anvil Architecture

> This document describes the current architecture. Update it when
> significant architectural decisions change.

The architecture is intentionally small and is the result of getting
Milestone 1 ("open a large CSV directly or inside a ZIP, browse it
smoothly") working. Every section below describes what the code actually
does today, not a future aspiration.

## Overview

Anvil is a native desktop application written in Rust using
[GPUI](https://gpui.rs). It is a single-binary, two-crate workspace:

- **`anvil_core`** (`src/lib.rs`) — a GUI-free crate exposing the data
  source, parser, indexer, archive handler, and open orchestrator.
- **`anvil`** (`src/main.rs`, `src/ui/**`) — a binary that depends on
  `anvil_core` and adds the GPUI application, main view, grid renderer,
  archive picker, and theme.

The headline architectural goals are:

1. **Separate presentation from data logic.** The `anvil_core` crate has
   no GPUI dependency and is fully exercised by `cargo test`. Every
   feature that touches data — parsing, indexing, archive handling —
   can be implemented and verified without launching a window.
2. **Bounded memory at multi-million rows.** Files are memory-mapped;
   records are addressed by byte offset; individual cells are decoded
   on demand from the mmap. The grid never instantiates a persistent
   GPUI element per row.
3. **Archives behave like ordinary files.** A ZIP entry becomes the
   same `ParsedDocument` a direct file would. The UI does not need to
   branch on whether the user opened a CSV or a CSV inside a ZIP.
4. **Lazy / asynchronous work.** Opening, extraction, and indexing run
   on GPUI's background executor. Results from obsolete generations are
   dropped, so dropping a second file while the first is still loading
   is safe.
5. **Measurement-driven optimisation.** Performance characteristics
   stated in the README and below come from running `anvil --probe`
   against the generated fixtures.

## Design Principles

The implementation is shaped by the following principles. Future
changes should preserve them unless an ADR is filed.

- **Native Rust + GPUI.** No webview, no Electron, no embedded browser.
- **Responsive UI.** Even while loading and indexing, the UI thread
  must remain responsive. Expensive work runs on `cx.background_executor`.
- **Large-file support.** A 165 MiB / 1,000,000-row fixture opens in
  under ~300 ms; the grid must not allocate per-row state.
- **Bounded memory.** Memory usage scales with `record_count × 8` bytes
  for the index, plus the mmap and (for ZIPs) the extracted temp file.
  No `Vec<Vec<String>>` materialisation.
- **Expensive work off the UI thread.** Opening, archive extraction,
  indexing, and (planned) search/filter/sort/statistics run on
  background tasks. The UI thread renders already-computed state.
- **Minimal copying / allocation.** Cell values are borrowed slices
  into the mmap; quoted cells with escape sequences allocate once.
- **Separation of presentation and data / query logic.** The parser
  knows nothing about GPUI. The UI knows the document only through the
  stable `ParsedDocument` / `LoadedDocument` surface.
- **Archive inputs behave like ordinary datasets.** A ZIP entry goes
  through the same indexing and rendering path as a direct file.
- **Measurement-driven optimisation.** `--probe` and the
  `measure_large_fixture` test exist precisely so performance
  regressions show up in CI and in the agent log.

### What is *current* vs *planned*

**Current (Milestone 1 + the Milestone 2 interaction/query slices + the Milestone 3 sort/type-inference foundation, in `src/`):**

- `parser::indexing` — build record byte-offset index, collect
  `ParseWarning`s, report `record_count` and `column_count`.
- `parser::delimit` — delimiter / quote / header detection on a
  64 KiB sample.
- `source::archive` — ZIP discovery, safety validation, extract-to-temp.
- `source::local` and `source::mod` — direct file mmap and dispatch.
- `loader` — open orchestration, including archive auto-open vs.
  multi-entry choice.
- `selection` — GPUI-free selection model: `(record, column)` cursor +
  anchor + `CellPos` coordinate type. Selected cells are painted with
  `theme::BG_SELECTED`; arrow / Page / Home / End /
  Cmd+Home / Cmd+End / Tab / Esc keys drive the cursor; click and
  shift-click on cells drive it too;
  `Selection::copy_text_with` renders TSV for clipboard paste.
- `query::search` — streaming search over `ParsedDocument` that
  returns matching record indexes in record order. `SearchOptions`
  carries `case_sensitive`, `column`, and `max_matches`. Case
  sensitivity is implemented with `memchr::memmem::Finder` for the
  case-sensitive path and a sliding-window ASCII lowercase for the
  case-insensitive path; the byte scan is SIMD-accelerated.
- `query::find_ranges` — given a cell's bytes and the needle,
  returns the byte ranges of every match. Used by the grid renderer
  to highlight the literal matched substring inside each cell.
- `query::sort` — `apply(doc, rows, &SortSpec) -> Vec<u64>` returns a
  stable permutation of the supplied row indexes. Numeric columns
  compare with `f64::total_cmp`; text compares case-insensitively on
  trimmed bytes; empty / non-numeric values sort last in both
  directions. Sorting composes with filtering because the caller
  passes the filtered set (or every record) as `rows`.
- `schema::infer` — samples up to 2048 rows per column and returns a
  `ColumnProfile` with an `Integer` / `Float` / `Boolean` / `Text` /
  `Empty` type and a `numeric_fraction` confidence. The sorter uses
  it to choose the comparison.
- `schema::stats` — `stats(doc, column, &StatsOptions) -> ColumnStats`
  scans one column for the inspector: counts, an exact-then-HLL
  [`DistinctCount`], duplicate count, min/max, longest/shortest,
  samples, and the top-N frequent values.
- `encoding` — `scan(doc) -> EncodingReport` makes one pass over the
  data records counting non-UTF-8 cells per column and detects a
  leading UTF-8 BOM. `Cell::is_utf8` is the per-cell flag; without it
  an invalid cell would silently render as empty (`as_str` falls back
  to `""`). The diagnostics panel runs `scan` on the background
  executor when it opens and lists the findings; `--probe` also prints
  them.
- `ui::view::diagnostics` — a warnings panel for the active document.
  It reads the immutable `ParseMeta.warnings` (no background task)
  and lists each warning's kind, row, and note, jumping the grid to the
  offending record on click; header-level warnings (`record_index ==
  None`) are listed but not navigable. It also runs `encoding::scan` on
  the background executor when it opens (generation-guarded by
  `encoding_generation`, cached until the document changes) and shows a
  BOM notice plus one row per column with non-UTF-8 cells.
- `ui::grid` — sticky-header + virtualized rows; visible-column window
  for horizontal virtualization. Per-cell `on_mouse_down` for
  selection. Matched search rows are tinted `BG_MATCH`; the active
  row uses `BG_MATCH_ACTIVE`; the literal matched substring inside
  each cell is drawn with a brighter `BG_MATCH_TEXT` background so
  the user can see *where* in the row the match is. Rows carrying a
  parse warning get a kind-aware marker in the row-number gutter
  (`✖` red for an unterminated quote, `⚠` warn otherwise), looked up
  from the `GridModel`'s cached, sorted warning index.
- `ui::commands` — pure `Keystroke` → `Action` binding table
  (`MoveCursor`, `Copy`, `Escape`, `OpenSearch`, `NextMatch`), with
  unit tests; no window or view state dependencies.
- `ui::view` — toolbar, tab strip, drag/drop, archive picker
  overlay, search bar overlay, status bar (with copy / error /
  match-count slot), generation counter for cancellation,
  `MainView::run_action` which executes intents decoded by
  `ui::commands`, and `MainView::on_search_key_down` which handles
  typed characters, Backspace, Enter, Shift+Enter, and Esc while
  the bar is open. `MainView` owns the multi-document tab list
  (`documents: Vec<DocumentSnapshot>` + `active: Option<usize>`);
  see "Multi-document / tabs" below.

**Planned (Milestone 4+ — these modules do not exist yet):**

- `diagnostics` — richer diagnostics surfaced in a panel and as
  navigation targets (jump to bad row).
- GPUI-native typed keybindings (`actions!`, `cx.bind_keys`) — the
  current `ui::commands` module centralizes key-to-intent mapping but
  still receives raw `Keystroke`s from `on_key_down`. GPUI typed
  actions could later add user-rebindable shortcuts, menu integration,
  and generated shortcut help. Shift-navigation needs distinct
  actions or a modifier-aware binding strategy.
- `tasks` — a uniform background-task wrapper if the existing
  per-feature `cx.spawn` pattern stops scaling.
- `docs/adr/` — ADRs for non-trivial decisions, numbered
  `0001-<slug>.md`.

Do not present the planned modules as if they already exist. Search
the source tree before assuming a capability is implemented.

## Application Architecture

### Window lifecycle

`src/ui/app.rs::run()`:

1. `Application::new().run(...)` — creates the GPUI runtime.
2. Opens a single 1200×800 window centred on the primary monitor with
   the title "Anvil".
3. Constructs a `MainView` (`src/ui/view.rs`) as the root view.

There is exactly one window today. Closing it exits the application
(this is GPUI default behaviour).

### Primary state / model ownership

The `MainView` owns a **multi-document tab list** plus the live
per-document fields for whichever tab is active. The tab list is the
source of truth for "which documents are open"; the live fields are a
mirror of the active snapshot so render and test code can keep
reading a single set of names.

`DocumentSnapshot` owns the per-document state that survives a tab
switch: a stable `id`, an optional parsed `Arc<ParsedDocument>`
(`None` for a ZIP entry that has not been extracted yet), the archive
/ entry pair for ZIP-backed tabs, a `loading` guard, the selection,
the horizontal scroll offset, the vertical scroll handle, the search
state, the filter state, and the copy-flash state.
`MainView::snapshot_active` copies
the live fields into `documents[active]`; `MainView::load_active`
copies the other way. `switch_to`, `close_active_at`, and `apply` are
the only callers that change `active`, so the mirror is always
consistent at the point render observes it.

`GridModel` wraps an `Arc<ParsedDocument>` and an `Arc<ColumnLayout>`.
Both are cheap to clone, so the uniform-list row renderer can capture
the model without aliasing `MainView` mutably.

### Event flow

1. User clicks **Open…** in the toolbar, or drops a path on the
   window. `on_drop` / `on_click(open-button)` call
   `MainView::begin_open`.
2. `begin_open` bumps `generation`, sets state to `Loading`, and
   spawns a task on `cx.background_executor` that calls
   `load_and_index` (which in turn calls `anvil_core::load`).
3. The task's result is delivered to the UI thread via
   `this.update(...)`. If `generation` has moved on, the result is
   silently discarded.
4. Otherwise, `apply` installs the new `GridModel` / archive and
   transitions to `Ready` (or `Error`, or the picker overlay).
5. The GPUI `Render::render` rebuilds the layout tree from `state`,
   `model`, and the various input handles.

### Actions / commands

There is **no GPUI typed `Action` layer** yet (no `actions!` macro or
`cx.bind_keys`). The toolbar `Open…` button and file picker (`rfd`)
remain the only actions wired through GPUI's typed-action system.

Keyboard bindings are now centralized in `src/ui/commands.rs`:

- `commands::action_for(&Keystroke) -> Option<Action>` is a pure
  keystroke-to-intent mapping. It handles arrow / Page / Home / End
  movement (including Shift extension), Cmd/Ctrl+Home/End row jumps,
  Tab / Shift-Tab, Cmd/Ctrl+C, and Esc.
- `Action` is a small UI-layer enum (`MoveCursor`, `NextCell`, `Copy`,
  `Escape`, `OpenSearch`, `NextMatch`), not a GPUI `Action` type.
  `PAGE_STEP` lives alongside the binding table. The module has unit
  tests that need no window.
- `MainView::on_grid_key_down` delegates to `action_for`; its
  `run_action` method executes the intent against view state (selection,
  clipboard, overlay). This keeps `commands` independent of `MainView`
  internals while removing the raw key-string match from `view.rs`.

This is the deliberately small extraction that makes new bindings
(search, filter, go-to-row, select-all) easy to add and test. It does
not yet provide user-rebindable shortcuts, menu integration, or a
shortcut cheatsheet. A later GPUI-native layer (`actions!` +
`cx.bind_keys`) can consume the same intents; Shift-navigation will
need distinct typed actions or a modifier-aware binding strategy.

Click handlers are wired via `cx.listener(|view, _, _, cx| ...)` for
toolbar / overlay clicks. Per-cell clicks are wired through
`Div::on_mouse_down(MouseButton::Left, ...)` and route into the view
via the captured `Entity<MainView>` handle, calling
`entity.update(&mut app, |view, cx| ...)`.

### Drag / drop

`MainView::on_file_drop` is wired via `div().on_drop(...)`. GPUI
delivers an `ExternalPaths`; every dropped path is opened and each
becomes its own tab. Dropping a directory or duplicate path is not
yet special-cased — the open task fails and the status bar shows the
error.

### Multi-document / tabs

Anvil keeps every opened file, and every usable ZIP entry, as a
separate document. The tab strip renders above the grid and below
the toolbar; it is zero-height when no documents are open. The state
model is:

- `documents: Vec<DocumentSnapshot>` — one entry per tab, in tab
  order. Each snapshot owns a stable `id` (from
  `MainView::next_doc_id`), an optional parsed document (see lazy
  loading below), the optional archive / entry pair for ZIP-backed
  tabs, and all the per-document UI state (selection, scroll,
  search, copy flash).
- `active: Option<usize>` — the active tab index, or `None`.
- The live per-document fields on `MainView` (`model`, `selection`,
  `scroll_x`, `search_*`, `copy_flash_*`, `v_scroll`, `archive`,
  `selected_entry`) mirror `documents[active]`.

Two helpers keep the mirror consistent:

- `snapshot_active` copies the live fields into `documents[active]`.
  It is called before any change of `active` (`apply`, `switch_to`,
  `close_active_at`) and before `close_search` so the snapshot sees
  the user's latest actions.
- `load_active` copies `documents[active]` into the live fields. It
  is called after every change of `active`; with `active == None` it
  falls back to `clear_live_per_document`. When the active snapshot
  has no document yet, `model` becomes `None` and the renderer shows
  a loading placeholder.

Opening:

- `begin_open` spawns a background task; its `OpenOutcome::Ready` is
  delivered to `apply`, which snapshots the previous tab, pushes the
  new tab(s), and makes one active.
- Multi-file drops call `begin_open` once per path, so each path
  becomes its own tab.
- A direct file becomes a single loaded tab.
- A ZIP-backed open (either `Ready` with an archive, or
  `NeedArchiveChoice`) calls `install_archive_tabs`. Every **usable**
  entry gets its own tab immediately: the ZIP central directory
  already lists names and sizes, so no decompression is needed to
  build the tab strip. The entry the loader pre-opened (when there
  is a clear favourite) is marked ready; the rest are pending.
- The modal archive picker is no longer shown automatically. It
  remains reachable from the toolbar's **Archive…** button to list a
  ZIP's contents (including skipped entries); clicking an entry calls
  `switch_to_entry`, which switches to the existing tab.

Lazy loading:

- A pending tab has `doc == None`. When it becomes active,
  `ensure_active_loaded` starts a background `load_entry` task (the
  same extract-to-temp + index path as a normal open) and sets
  `loading` so repeated switches do not duplicate the work. The task
  is detached, so switching away or opening another file does not
  cancel it and leave the tab permanently stuck.
- On completion `apply_lazy_result` looks the tab up by `id`, stores
  the parsed document, and rebuilds the live model if the tab is
  still active. If the tab was closed while loading, the result is
  discarded. If extraction failed, the tab is removed and the error
  goes to the status bar.

Closing / switching:

- `switch_to(index)` snapshots the current tab, moves `active`,
  loads the new snapshot, and calls `ensure_active_loaded`. It also
  sets `focus_grid_on_next_frame` so the grid takes keyboard focus.
- `close_active_at(index)` removes the snapshot, adjusts `active` to
  the neighbour (or `None`), and triggers a load if the neighbour is
  pending. Closing the last tab resets `state` to `Empty` so the
  welcome screen returns.

Presentation — tab strip and file panel:

- The tab strip sits between the toolbar and the body. Tabs are
  `flex_shrink_0`, so a long list keeps its natural widths; the
  inner track is `overflow_x_scroll()` and tracked by
  `MainView.tab_scroll`, so distant tabs stay reachable by scrolling.
- The left-hand file-manager panel (`render_file_panel`) lists every
  open document. `group_documents` groups consecutive snapshots that
  share an archive by `Arc` identity (direct files are top-level
  rows, ZIP entries are nested under an archive header), so two
  archives with the same entry name stay separate. Each row has an
  active highlight, a loaded/pending dot, and a × that calls
  `close_active_at`; clicking the row calls `switch_to`.
- The panel is shown when `file_panel_open && !documents.is_empty()`.
  It is toggled by the toolbar **Files** button, its own × , and
  `Action::ToggleFilePanel` (Cmd/Ctrl+B). It is a `flex_shrink_0`
  sibling of the grid body with a fixed width, so the grid takes the
  remaining space and reflows when the panel is hidden.

Status / error behaviour:

- With at least one tab open, the active document is always rendered;
  a pending active tab shows a `Loading…` placeholder.
  `Empty` / `Loading` / `Error` only take over when `active == None`.
- An error from a background open task sets `status_message` and does
  not tear down the current tab. When no tab is open it also sets
  `state = Error`, so the welcome area shows the failure.

Tabs are a UI-layer concern only: `anvil_core` has no notion of a tab
list. Each `DocumentSnapshot` holds an `Arc<ParsedDocument>`, so
documents are not duplicated; the tab bar just indexes into them.

### Keyboard handling

The grid div carries `key_context("Grid")`, `.track_focus(&self.focus_handle)`,
and an `on_key_down` listener that delegates to
`MainView::on_grid_key_down`. **Focus is a prerequisite**: GPUI only
delivers key events to the focused element's path, so without
`track_focus` the listener never runs and the whole keyboard surface
(arrows, Page Up/Down, Home/End, Esc, Cmd/Ctrl+C) is dead. This was a
real bug for one iteration; two UI regression tests now fail if the
grid stops tracking focus (see Testing).

Focus is moved to the grid:

* when a document becomes ready — `apply` sets
  `focus_grid_on_next_frame`, and `render_grid` schedules a deferred
  `window.focus` (focus is not mutated mid-render, which can re-enter
  the frame); and
* on any mouse-down inside the grid — `.track_focus` registers a
  bubble-phase listener that focuses the grid, so clicking a cell then
  pressing Cmd/Ctrl+C works.

Recognised keys:

| Key            | Action                                                       |
|----------------|--------------------------------------------------------------|
| Arrow keys     | Move the selection by one cell.                              |
| Page Up/Down   | Move the selection by `commands::PAGE_STEP` rows.              |
| Home / End     | Jump the column cursor to the first / last column.           |
| Cmd/Ctrl+Home  | Jump the row cursor to the first row (column preserved).     |
| Cmd/Ctrl+End   | Jump the row cursor to the last row (column preserved).      |
| Tab / Shift-Tab | Move to the next / previous cell in row-major order, wrapping across rows and around the document ends. With a filter active the walk covers visible rows only. |
| F3 / Shift-F3  | Advance to the next / previous search match (no-op when no search is active). |
| Esc            | Close the search or filter bar if open (whichever is up), else clear the selection, else close the archive picker. |
| Cmd/Ctrl+C     | Copy the current selection to the clipboard as TSV; status bar reports "copied N cells" or "copy failed: ...". |
| Cmd/Ctrl+F     | Open the search bar overlay; if the filter bar is open, switch to search (closing it first). No-op when search is already open. |
| Cmd/Ctrl+L     | Open the filter bar overlay; if the search bar is open, switch to filter (closing it first). No-op when filter is already open. |
| Cmd/Ctrl+Shift+L | Open the natural-language **Ask** bar; previews a Tier 1 parse and accepts it into the filter bar. |

`commands::action_for` maps each `Keystroke` to a logical
`commands::Action`; `MainView::run_action` executes it. Shift held
during arrow / Page / Home / End / Cmd+Home / Cmd+End becomes
`MoveCursor { extend: true }`. Cmd/Ctrl+Home/End carry an
`i64::MIN` / `i64::MAX` row delta; `Selection::move_cursor` uses
saturating arithmetic so those extremes clamp at the document edges
rather than overflowing. Tab / Shift-Tab decode to
`Action::NextCell` and dispatch to `MainView::move_cell_selection`,
which delegates to `Selection::move_cell` (or walks the visible rows
when a filter is active). Cmd/Ctrl+C and Cmd/Ctrl+F match
`keystroke.modifiers.secondary()`
(Cmd on macOS, Ctrl on Linux/Windows) with no Alt/Fn; this avoids
eating variant chords like `Alt+C` or `Alt+F`. The existing
`key_context("Grid")` remains ready for a future GPUI `actions!` /
`cx.bind_keys` layer if we add user-rebindable shortcuts or menu
integration. The search bar carries its own `key_context("Search")`
and `track_focus(&self.search_focus_handle)`, so typed characters
route through `MainView::on_search_key_down` rather than the grid
handler.

## Selection model

`Selection` lives in `src/selection.rs` (re-exported from
`anvil_core::Selection`). It is GPUI-free and has no `unsafe`.

A `Selection` carries an optional cursor and anchor. The cursor is
the cell the user has most recently acted on; the anchor is the
cell where the current range selection started. A range selection is
identified by `cursor != anchor`. `Selection::normalize()` returns
the top-left and bottom-right corners of the rectangle in row-major
order; `Selection::contains(record, column)` does an inclusive test.

### Operations

| Method                          | Meaning                                       |
|---------------------------------|-----------------------------------------------|
| `Selection::empty`              | New empty selection.                          |
| `Selection::single(pos)`        | One-cell selection, no range.                 |
| `selection.set(pos)`            | Replace selection with a single cell.         |
| `selection.extend_to(pos)`      | Move cursor to `pos`, keep anchor fixed.      |
| `selection.move_cursor(dr, dc, columns, records, extend)` | Translate cursor by `(dr, dc)` with saturating arithmetic, clamp to document bounds; preserve anchor if `extend`. `i64::MIN` / `i64::MAX` deltas express the document edges. |
| `selection.move_cell(forward, columns, records, extend)` | Move to the adjacent cell in row-major order (Tab / Shift-Tab), wrapping across rows and around the document ends. |
| `selection.clear()`             | Empty the selection.                          |
| `selection.cursor()`            | Current cursor cell (or `None`).              |
| `selection.anchor()`            | Current anchor cell (or `None`).              |
| `selection.normalize()`         | Top-left + bottom-right of the rectangle.     |
| `selection.contains(r, c)`      | Is `(r, c)` inside the rectangle?             |
| `selection.cell_count()`        | Number of data cells in the rectangle (0 if empty). |
| `selection.copy_text_with(cell_at)` | Render the selection as TSV.            |

### Invariants

* Cursor and anchor are `Option<CellPos>` so "nothing selected" is
  representable without sentinel coordinates.
* `set` always produces a single-cell selection (cursor == anchor).
* The first call to `move_cursor(..., extend=true)` from an empty
  selection anchors at the implicit origin `(0, 0)` so that the very
  first shift-arrow produces a real range.

### Grid integration

* `MainView.selection` is reset on every successful `OpenOutcome`.
* `render_row` paints cells inside the rectangle with
  `theme::BG_SELECTED` (see `ui/grid.rs::render_row`).
* Mouse click on a cell: `Selection::set(pos)`; shift-click:
  `Selection::extend_to(pos)`. Both go through the captured
  `Entity<MainView>` handle and call `cx.notify()` to re-render.
* Click-and-drag: a mouse-down on a cell arms `drag_selecting`; every
  cell also carries an `on_mouse_move` handler, and while
  `MouseMoveEvent::dragging()` is true and `drag_selecting` is set, the
  handler calls `Selection::extend_to(pos)` for whichever cell the
  pointer is over. A mouse-up (bubble over the grid, or
  `on_mouse_up_out` capture when the pointer has left it) disarms.
  Because each cell is its own hitbox, this needs no coordinate
  arithmetic and no vertical-scroll bookkeeping. `drag_selecting`
  guards the case where a drag began outside the grid and passes over
  cells.
* Drag auto-scroll: per-cell handlers cannot see the pointer once it
  leaves the grid, so an overlay `canvas` (no hitbox, so it does not
  intercept input) records the scroll area's bounds and installs a
  global `window.on_mouse_event` mouse-move listener. When
  `drag_selecting` is set and the pointer is above/below
  `grid_bounds`, `auto_scroll_step` extends the selection to the row
  at that edge and asks the list to pin the next row to the top
  (`scroll_to_item_strict(.., ScrollStrategy::Top)`). A
  `cx.spawn` tick loop (`AUTO_SCROLL_TICK`, 30 ms) repeats this while
  the pointer is held still outside the edge; the loop exits when
  `drag_selecting` clears.
* Keyboard: `MainView::on_grid_key_down` routes arrow / Page /
  Home / End / Cmd+Home / Cmd+End keys through
  `Selection::move_cursor`, and Tab / Shift-Tab through
  `Selection::move_cell`. Shift extends a range.

### Architectural invariants preserved

* `Selection` is owned by `anvil_core`, not the UI crate; it has no
  GPUI types in its public surface. The grid renders from it, the
  keyboard handlers write to it, the (future) clipboard reads from
  it. They all agree on the same data type.
* `Selection::move_cursor` is `O(1)`; we never iterate cells to
  decide whether a key needs handling.

### Open loops

* Drag auto-scroll only triggers when the pointer is fully outside the
  list's vertical bounds; there is no proximity margin, and the speed
  is a fixed one row per tick (no proportional acceleration).
* The `commands` module that will own keybindings (search, filter,
  copy) is not yet extracted. Today keybindings are inlined in
  `view.rs::on_grid_key_down`.

## Editable text inputs

GPUI 0.2.2 ships no `TextInput` element, so the filter bar implements
editing itself. The state machine is
`ui::text_edit::TextEdit` (`src/ui/text_edit.rs`), which is GPUI-free
and unit-tested without a window:

* `text` plus a `caret` and an `anchor` (both byte offsets, always on a
  UTF-8 char boundary). `anchor == caret` means no selection.
* `insert` replaces the selection; `backspace` / `delete` remove the
  selection or the adjacent character; `move_left/right/home/end/word_*`
  and `select_all` move or extend the caret.
* This mirrors `anvil_core::Selection` for the grid: a small pure model
  the UI drives, so the editing logic is testable end to end.

Rendering (`ui::input::editable_text_area`, used by both
`render_search_bar` and `render_filter_bar`) paints the text with
`StyledText` and, for a non-empty selection, a `BG_SELECTED` highlight
range. The caret is a 1px bar positioned from
`text_caret_x(window, text, caret)`, which shapes the line with
`window.text_system().shape_line(..)` and reads `x_for_index`. The same
shape call is used on mouse-down/drag to map window-space pointer x to
a byte index via `closest_index_for_x`.

The shaping uses the field's rendered size (`input_font_size`, the same
`text_sm` 0.875rem the field draws at), **not** `window.text_style()`'s
default 1rem: `window.text_style()` during render is unrefined, so
shaping at the default made the caret drift progressively ahead of the
glyphs as the text grew. `editable_text_area` now sets `.text_sm()`
explicitly so the two sizes cannot diverge.

The text area's window bounds are recorded each frame by a hitbox-free
`canvas` overlay (`filter_text_bounds` / `search_text_bounds`), reusing
the pattern already used for the grid's drag auto-scroll. Mouse
handlers on the area place the caret (`set_caret(index, shift)`), arm a
`filter_dragging` / `search_dragging` flag on press, extend the
selection while the pointer is dragged, and clear the flag on release.
Each bar keeps its own `key_context` and focus handle;
`on_filter_key_down` / `on_search_key_down` map the edit keys onto
`TextEdit` operations (Option/Ctrl+arrows for word movement on
macOS/other platforms, Cmd/Ctrl+A for select-all, Enter to apply, Esc
to close). Both bars also render a visible `×`
(`filter-close` / `search-close`) wired to `close_filter` /
`close_search`, so dismissing them never depends on knowing the
shortcut; the grid's `Action::Escape` closes whichever bar is open
even after focus has returned to the grid.

Both the filter and search inputs use `TextEdit`. The same
`render_filter_bar` pattern is repeated in `render_search_bar`:
`StyledText` + selection highlight, a shaped caret, a bounds-recording
`canvas`, and mouse handlers that place/extend the caret. The search
differs only in that any text change re-runs the live background
search (`kick_search`), while the filter applies on Enter.

There is no caret blink and no horizontal scroll when the text is
wider than the field; both are follow-ups.

## Clipboard copy

Cmd/Ctrl+C copies the current selection as a TSV string onto the
system clipboard. The data-side formatter (`Selection::copy_text_with`)
lives in `anvil_core`; the platform call lives in the UI crate.

### Data-side formatter

`Selection::copy_text_with<F>(&self, cell_at: F) -> String` where
`cell_at: Fn(u64, usize) -> Option<String>`. The closure decouples
the formatter from `ParsedDocument` so unit tests can use mock cells
and the UI passes `|r, c| doc.cell(r, ColumnIndex(c)).map(...).into_string())`.

The output is RFC 4180-style quoted TSV:

- Cells are joined by `\t`. Rows are joined by the platform's
  standard line ending (LF on Unix, CRLF on Windows).
- A cell that contains a tab, newline, carriage return, or
  double-quote is wrapped in double-quotes with embedded
  double-quotes doubled. Plain cells are emitted raw.
- Out-of-bounds cells (the row is shorter than the rectangle's
  width) become empty strings rather than panicking.
- An empty selection produces the empty string.

`Selection::cell_count()` returns the rectangle's cell count and is
used for the "copied N cells" status message.

### UI wiring

`MainView::copy_selection_to_clipboard(cx)` runs on the UI thread.
It:

1. Returns early if there is no selection (`cell_count == 0`).
2. Clones the `Arc<ParsedDocument>` and `Selection` so the closure
   does not borrow `MainView` mutably.
3. Formats the selection via `Selection::copy_text_with`.
4. Calls the injected `ClipboardWriter` (default `arboard`) with the
   text. On error, captures the message but does not panic.
5. Stores either `copied N cells` or `copy failed: ...` in
   `MainView.status_message`, which `render_status` paints in
   `theme::ACCENT` (or `gpui::red()` for failures) ahead of the
   generic state line.
6. On success, calls `start_copy_flash`: it records the normalized
   selection rectangle in `copy_flash_rect`, bumps
   `copy_flash_generation`, and spawns a detached
   `background_executor().timer(COPY_FLASH_DURATION)` task that clears
   the rectangle (and calls `cx.notify`) if its generation is still
   current. Copying again during a flash bumps the generation, so the
   new flash is not cleared early by the previous timer.
7. `status_message` is cleared on every `OpenOutcome`, and
   `copy_flash_rect` is cleared there too. Neither is auto-expired
   beyond the flash timer; the next user action that changes state
   resets the message.

### Copy confirmation flash

As immediate positive feedback, the copied cells flash green
(`theme::BG_COPIED = #2f8f4f`) for `COPY_FLASH_DURATION` (450 ms)
before returning to the normal selection colour. `grid::render_row`
takes `copy_flash: Option<(CellPos, CellPos)>`; a cell inside the
rectangle is painted `BG_COPIED` in preference to `BG_SELECTED`, and
a full-width rectangle also tints the row gutter. The flash rectangle
is captured at copy time, so moving the selection during the 450 ms
does not move the green feedback; it still marks what was copied.
This is a UI-layer concern only — `anvil_core` is unchanged.

### Keyboard binding

`on_grid_key_down` matches `key == "c"` with `modifiers.secondary()`
(Cmd on macOS, Ctrl on Linux/Windows), no alt, no function. The
explicit modifier check avoids eating `Alt+C` or `Fn+C` when they
become bound by other features.

### Architectural invariants preserved

- The formatter lives in `anvil_core` and has no platform dependency;
  the entire test suite (25 selection unit tests + 8 copy integration
  tests) exercises it without launching the GUI.
- Only the cells inside the selection rectangle are decoded; we do not
  re-decode every cell in the visible range. For a 1M-row document
  with a 20×10 selection, the formatter decodes 200 cells total.
- Copy uses the borrowed `ParsedDocument` mmap through `doc.cell`;
  the text is converted to `String` only at the clipboard boundary,
  consistent with "owned strings only at the UI boundary".

### UI update flow

`Render::render` rebuilds:

```
div (column, flex-1)
├── toolbar       (render_toolbar)
├── center        (render_center → Empty | Loading | Error | grid)
└── status bar    (render_status)
```

The grid uses `gpui::uniform_list` so only rows in the visible range
are built per frame. The header is rebuilt each frame because visible
columns change with horizontal scroll. `cx.notify()` is called
whenever the `generation`, `model`, `scroll_x`, or any state changes
that should cause a re-render.

## Data Source Model

The crate has two layers:

```
DataSource     — high-level description of the input
                 ("local file" or "archive entry inside named.zip")
OpenedSource   — physically resolved: an mmap of the selected bytes,
                 plus optional archive candidates and a temp-dir handle
```

`open_path` sniffs the first 4 bytes (without reading the whole file
into RAM) and dispatches:

- `PK\x03\x04` or `PK\x05\x06` → `OpenResult::Archive(ArchiveSource)`
- otherwise → `OpenResult::Direct(OpenedSource)` with an mmap

The UI calls `anvil_core::load(path)`, which is the higher-level
orchestrator in `src/loader.rs`:

```
load(path) →
  match open_path(path):
    Direct(opened)             → index_opened → LoadResult::Ready
    Archive(source) with
      total_candidates() == 0   → Err(NoUsableEntries)
      one best-ranked entry     → load_entry → LoadResult::Ready
      several equally-ranked    → LoadResult::NeedArchiveChoice(source)
```

### Direct file

```
file -> open_path (4-byte sniff) -> MmapSource::open
     -> OpenedSource { physical = Arc<MmapSource>, temp_dir = None,
                       archive_candidates = None }
     -> loader::index_opened (parse -> indexing::build)
     -> ParsedDocument { opened, meta, record_offsets }
     -> GridModel::new (ColumnLayout::compute)
     -> uniform_list row renderer
```

### ZIP

```
ZIP -> open_path (4-byte sniff) -> ArchiveSource::from_path
     -> ZipArchive::new; for each entry:
          evaluate_entry(name, sizes, flags)
          -> (usable, rank, rejected_reason)
     -> ArchiveSource { candidates, archive_file }

UI / loader -> best_candidate(source):
     - rank usable entries; if exactly one at the best rank → auto-open
     - else NeedArchiveChoice

load_entry(source, entry):
     - ZipArchive::new (try_clone of file handle)
     - reject encrypted entries (AnvilError::EncryptedEntry)
     - reject unsupported compression methods
     - reject size > MAX_DECOMPRESSED_BYTES
     - copy entry bytes into tempfile::tempdir()/sanitize_filename(entry)
     - track cumulative decompressed bytes vs. compressed ratio
       (zip-bomb guard)
     - MmapSource::open(temp file)
     - return OpenedSource {
         physical = Arc<MmapSource>,
         temp_dir = Some(Arc<TempDir>),
         source.kind = ArchiveEntry { archive_name, entry_name,
                                     compressed_size, uncompressed_size },
         archive_candidates = Some(self.candidates.clone()),
       }
     - index_opened -> ParsedDocument -> GridModel

Cleanup:
     - OpenedSource owns Arc<TempDir>. Dropping it removes the temp
       dir. The Arc<MmapSource> inside it is independent; once the
       grid is replaced the previous OpenedSource (and its temp dir)
       are dropped.
```

## Archive Handling

`source/archive.rs` is the only place that touches the `zip` crate.

### Candidate discovery

`ArchiveSource::new` opens the file once via `ZipArchive::new`,
captures each entry's name + sizes (without decompressing), and runs
`evaluate_entry(name, sizes)` to classify each.

### Supported file detection

`evaluate_entry` rejects:

- directories
- paths containing `__MACOSX/`, `/.DS_Store`, leading `.`
- paths containing `..` (and `new` returns `AnvilError::PathTraversal`
  immediately for any candidate whose name contains `..`)
- sizes exceeding `MAX_DECOMPRESSED_BYTES`
- anything without a recognised extension
- encrypted entries (reason `REJECTED_ENCRYPTED`), so a
  password-protected data file is reported rather than opened and then
  failed
- a compression method the `zip` crate cannot decode
- an uncompressed/compressed ratio above `MAX_COMPRESSION_RATIO`
  (checked from the central directory before any bytes are copied)

Each rejected candidate keeps its `rejected_reason`; the archive picker
shows the reason for every skipped entry.

Recognised extensions (with rank):

| Extension                              | Rank |
|----------------------------------------|------|
| `csv`, `tsv`, `tab`, `psv`             | 0    |
| `dat`, `out`                           | 1    |
| `txt`                                  | 2    |

Lower rank means "more likely to be the dataset the user wants".

### One-entry behaviour

If exactly one usable candidate exists, `ArchiveSource::single_usable`
returns it. `loader::load` auto-opens it.

If exactly one candidate exists at the **best rank** (e.g. one CSV
alongside a README), it is auto-opened even when there are other
usable-but-lower-rank entries. The `best_candidate` helper in
`loader.rs` is the authority.

### Multi-entry behaviour

If multiple candidates share the best rank, `loader::load` returns
`LoadResult::NeedArchiveChoice(Arc<ArchiveSource>)`. The UI then gives
every usable entry a tab and keeps the archive picker reachable from the
toolbar's **Archive…** button. The overlay lists the usable entries and
a *skipped entries* section that shows each rejected entry's name and
`rejected_reason` (capped at 40 rows with an "…and N more" summary).
Clicking a usable entry switches to its tab via `switch_to_entry`.

When an archive has candidates but every one of them is encrypted,
`loader::load` returns `AnvilError::EncryptedEntry(name)` rather than the
generic `NoUsableEntries`, so the status bar names the file.

### Extraction / decompression

`ArchiveSource::extract_into_temp(entry_name)`:

1. Validates encryption, compression method, and total uncompressed
   size up front. An encrypted entry returns
   `AnvilError::EncryptedEntry`, not a generic error.
2. Creates a `tempfile::tempdir()` (auto-removed on drop).
3. Sanitises the entry name to a basename (no directory components,
   no `..`, no NUL).
4. Reads the entry into a 1 MiB buffer, writing to the temp file in
   1 MiB chunks.
5. During the copy, aborts if the cumulative decompressed size
   exceeds `compressed_size * MAX_COMPRESSION_RATIO` (default 200).
   This is the zip-bomb guard.
6. `sync_all()` and `drop` the writer.
7. `MmapSource::open` on the temp file.

### Temp files

Stored in `tempfile::tempdir()`, typically `$TMPDIR` on macOS/Linux.
The `Arc<TempDir>` is held by `OpenedSource.temp_dir`. Dropping the
`OpenedSource` removes the temp directory and its contents.

When the user opens a new file, the old `GridModel` is replaced and
its underlying `ParsedDocument` (which owns the `OpenedSource`) is
dropped, cleaning up the previous archive's temp files.

### Cleanup

Implicit, via `Drop` on `TempDir`. There is no manual cleanup path.

### Path validation

Two layers:

- `evaluate_entry` rejects names containing `..` and the entry is
  marked unusable.
- `new` additionally returns `AnvilError::PathTraversal` immediately
  if any candidate's name contains `..`, even though it would have
  been unusable anyway. This guarantees a traversal attempt is a hard
  error, not a silent skip.

`extract_into_temp` writes to `sanitize_filename(entry_name)`, which
strips directory components and replaces path separators / NUL with
underscores, so the resolved path always stays inside the temp dir.

### Archive safety

Implemented guards:

- Magic-byte sniff → no zip → no archive code path.
- Encryption rejected at extraction time.
- `Stored`, `Deflated`, `Bzip2` allowed; everything else rejected
  with `UnsupportedCompression`.
- Hard size cap `MAX_DECOMPRESSED_BYTES` (8 GiB).
- Compression-ratio guard `MAX_COMPRESSION_RATIO` (200) checked
  against the central-directory sizes at listing and again while
  copying, so a high-ratio entry is skipped before it is extracted.
- Encryption rejected at listing with a recorded reason, and again at
  extraction with the typed `EncryptedEntry` error.
- Path traversal rejected.
- Duplicate entry names do not panic (covered by a test).

### Current limitations

- No streaming extraction. Every extraction writes the full entry to
  disk before parsing. The temp file is then mmapped. Streaming into
  the indexer is possible but not implemented (see "Planned
  Architectural Evolution").
- No support for other archive formats (`gz`, `tar.gz`, `7z`).
- Encryption is rejected outright; there is no password prompt.
- No progress signal during extraction. The UI shows a generic
  `Loading…` label.
- `ZipArchive::new` consumes a `File`; the archive source keeps a
  `try_clone` and re-opens the file for each entry. For huge archives
  with many entries this could be slow; not currently a bottleneck.

## Parsing and Row Indexing

### Parser implementation

`parser/mod.rs` provides:

- `Cells<'a>` — a quote-aware iterator over a single record's cells.
  `at_field_start` (implicit via the cursor position) ensures a quote
  mid-value is a literal character.
- `Cell<'a>` — a `Cow<'a, [u8]>` borrowing the slice, owned only when
  the cell contained escaped quotes that needed rewriting
  (`unquote_cell`).
- `cell_at(record, col, delim, quote)` — convenience for the
  single-cell use case; equivalent to `Cells::new(...).nth(col)`.
- `ParsedDocument` — owns the `OpenedSource` plus the index, and
  exposes `record_bytes`, `cell`, and `record_strings`.

### Delimiter handling

`parser/delimit.rs::detect` runs on the first `SAMPLE_BYTES` (64 KiB):

1. Split into logical lines honouring quoted fields.
2. For each candidate delimiter (`,`, `\t`, `;`, `|`), score:
   - the cell count on the first line;
   - the most-frequent cell count across all sampled lines;
   - the fraction of lines that match the chosen count.
3. Pick the candidate with the highest `(columns, consistency)` score;
   tie-break is `CANDIDATES` order (comma first).
4. Decide whether the first line is a header (see below).
5. Decode the header cells into `Vec<String>`.
6. Emit `EmptyHeader` / `DuplicateHeader` warnings while collecting
   headers.

`detect(bytes)` is `detect_with(bytes, HeaderMode::Auto)`. `HeaderMode`
(`Auto` / `Header` / `Headerless`) lets callers force the
interpretation; it is carried on `IndexOptions` and threaded through
`indexing::parse_with`. Force modes skip the heuristic entirely
(`Headerless` never emits header warnings).

Under `Auto`, `looks_like_header_in_context` compares the first row's
per-column *textness* (empty / typed / text) against up to
`HEADER_CONTEXT_ROWS` (20) following logical lines:

- **header vote** — a text cell above a typed (numeric/boolean)
  value, the classic `name` over `42` shape;
- **data vote** — a typed cell above a typed value, i.e. the first row
  looks like another data row.

Text-over-text is deliberately *not* a data vote, so
`first_name,last_name` over `alice,bob` keeps defaulting to a header.
When the votes tie, or there is nothing to compare, it falls back to
the earlier local `looks_like_header` rule (at least half the first
~8 non-empty cells numeric/boolean ⇒ data). This means a genuinely
ambiguous all-text file still defaults to a header, which is what the
user override exists for.

### Header handling

`has_headers` is a flag derived from the detection. The header row is
**pre-decoded** at index time so the grid can render it cheaply for
every frame. `meta.headers: Vec<String>` is owned; `meta.column_count`
is derived from `headers.len()` when headers are present.

For headerless files, `column_count` is the maximum cell count across
the indexed records, and display names come from
`parser::column_label` / `ParseMeta::column_label`: `col0`, `col1`, …
consistently across the grid header, search scope chip, sort label,
column inspector, and encoding scan.

The UI toolbar **Headers** control cycles `Auto → Header → Headerless`.
Forcing a mode calls `anvil_core::reindex(&doc, options)`, which
re-runs `indexing::parse_with` against the *same* `OpenedSource` (the
`MmapSource` and extraction `TempDir` are shared behind `Arc`s, and
`OpenedSource` is `Clone`), so there is no re-open or re-extract. The
task runs on the background executor under the open `generation`
guard; on completion the active tab's `Arc<ParsedDocument>` and
`GridModel` are swapped, filter/sort/search results are reset (row
indexes shift by one), and an out-of-range selection is cleared. The
mode is stored per tab on `DocumentSnapshot`.

### Row boundary indexing

`parser/indexing.rs::build` walks the file once and pushes a byte
offset into `record_offsets` for every record. The list always ends
with `total.len()`, so any record `i` has an exclusive end at
`record_offsets[i + 1]`. This means we have `record_count + 1`
entries and a uniform `O(1)` slice per row.

The walker tracks:

- `in_quotes` — quote state carried across newlines, so embedded
  newlines inside quoted fields merge lines into a single record.
- `at_field_start` — distinguishes `quote` at the start of a field
  from `quote` mid-value.
- `record_has_content` — distinguishes the trailing record without a
  newline from the empty tail of an already-completed record.

The walker takes an [`IndexOptions`](`crate::IndexOptions`) (default
`max_record_bytes = DEFAULT_MAX_RECORD_BYTES`, 1 MiB). After the walk,
a post pass over the finished offset table emits a `VeryLongRecord`
warning for any record longer than that limit (including its trailing
newline). `build`/`parse` use the default options; `build_with` /
`parse_with` take explicit ones so tests can exercise the threshold on
a tiny fixture.

### Random row access

```rust
let (start, end) = record_range(i)?;  // from record_offsets
let bytes = opened.bytes();            // the mmap
let cell  = Cells::new(&bytes[start..end], delim, quote).nth(col)?;
```

This is `O(record length)` per cell, not `O(file length)`. For most
CSV inputs that is effectively constant because most records are
short relative to the whole file.

### `mmap` usage

`memmap2::Mmap` via `MmapSource::open`. The mmap is held behind an
`Arc` inside `OpenedSource`. For small files this is identical to
`read_to_end`; for very large files the OS keeps the mmap lazy and we
get page-cache benefits for repeated access.

### Caching

There is **no** result cache today. Each cell render re-decodes from
the mmap. This is a deliberate trade-off: the cell decoder is a
linear scan of <100 bytes in the common case, and avoiding a cache
keeps the architecture simple. A small LRU cache per scroll position
is a plausible future optimisation.

### Lazy work

Everything observable (parsing, indexing, extraction, decoding) is
lazy in the sense that it happens once per open and only what is
needed for the current viewport is rendered. There is no eager
pre-decoding of all cells.

### Permanently stored data

Per `ParsedDocument`:

| Field           | Bytes/row         | Notes                              |
|-----------------|-------------------|------------------------------------|
| `opened`        | constant          | `Arc<MmapSource>` + metadata       |
| `record_offsets`| 8 (`u64`)         | `Vec<u64>` length `record_count+1` |
| `meta.headers`  | per-header        | `Vec<String>` of header names      |
| `meta.warnings` | per-warning       | `Vec<ParseWarning>`                |
| temp file       | full entry bytes  | only when source was a ZIP entry   |

A 1,000,000-row file costs ~8 MB of offsets plus the 173 MB mmap.

### Allocations

The hot path (`render_row`) currently calls `cell(...).into_string()`
for every visible cell, which allocates a `String` per cell. For the
20-column 1M-row fixture this is bounded by `visible_rows × columns`
(~50 rows × 20 cells = 1,000 small allocations per redraw). We have
**not** yet converted this to the borrowed `&str` path; it is an
intentional follow-up for Milestone 2 (text shaping + selection need
ownable strings anyway).

## Grid Rendering

### Virtualization

GPUI's `uniform_list("anvil-grid", row_count, cx.processor(...))`.
`render_row` is called only for the rows in the visible range.

### Visible row calculation

`uniform_list` owns the visible range. It is driven by the scroll
container that hosts the list.

### Scrolling

Vertical: GPUI default for `uniform_list`.

Horizontal: an `f32 scroll_x` field on `MainView`. Updated by:

- `on_grid_scroll` (mouse wheel) — `delta.x` (in pixels or lines).
- A custom horizontal scrollbar in `render_h_scrollbar` with drag
  support via `on_mouse_event(MouseDown/Move/Up)`.

The header and each row translate by `-scroll_x` and pad the left
edge to the offset of the first visible column, so columns line up
across the header and data rows.

`MainView.viewport_w` is the columns area's width. It is **computed
synchronously** from the window width minus the row-number gutter and
the fixed width of every panel currently sharing the grid's flex row
(`grid_viewport_width`: file panel, inspector, diagnostics — all
`flex_shrink_0` with a `theme` constant). Because the arithmetic uses
the same conditions as the panel layout in `render`, it is exact and,
crucially, correct on the same frame a panel is shown or hidden.
An earlier version read the previous frame's measured `grid_bounds`,
which left the table at the old width for one to two frames after a
panel toggle (a visible blank gap) until the overlay canvas re-measured
and notified. `grid_bounds` is still recorded for drag auto-scroll,
which needs the real on-screen rectangle.
`scroll_horizontal`, `ensure_column_visible`,
`ColumnLayout::visible`, and `render_h_scrollbar` all read the one
`viewport_w` value.

### Column rendering

`ColumnLayout` (in `ui/grid.rs`) is computed once when the document
opens. It holds `widths: Vec<f32>` and `offsets: Vec<f32>`, where
`offsets[i]` is the cumulative pixel offset of column `i`. `total`
is the sum of `widths`.

`ColumnLayout::compute` samples up to `SAMPLE_ROWS` (200) records per
column and picks the widest cell (plus padding) as the column width.
Only the first `MAX_MEASURED_COLUMNS` (4096) columns are actually
measured; columns beyond that use `DEFAULT_COLUMN_WIDTH`. Widths are
clamped to `[MIN_COLUMN_WIDTH, MAX_AUTO_WIDTH]` (48 px – 360 px).

`ColumnLayout::visible(scroll_x, viewport_w)` uses `binary_search_by`
on `offsets` to find the first visible column, then walks forward
while the column's offset is inside the viewport.

### Row retrieval

Inside `cx.processor`, `grid::render_row` is invoked per visible row.
The per-frame inputs (`selection`, `scroll_x`, `viewport_w`,
`copy_flash`, `search_*`, and the sorted `warning_rows` slice) are
bundled once into a `grid::RowContext` and passed by
reference, so `render_row` keeps a small argument list as more
per-frame state is added. Each row:

1. Decides which columns are visible (`ColumnLayout::visible`).
2. Renders a leading gutter div (`ROW_NUMBER_WIDTH`) with the row
   number (`index + 1`); a warning row is prefixed with `⚠` and
   coloured `theme::WARN`.
3. Renders a flex row of cell divs for the visible columns only, each
   with `on_mouse_down` (selection) and `on_mouse_move` (drag-select)
   handlers.
4. Alternates background colour for odd-indexed rows.

### How millions of persistent UI nodes are avoided

- The grid uses `uniform_list`, so only visible rows are built into
  the GPUI element tree.
- Within a row, only visible columns are built.
- The grid is rebuilt every frame, but `Render::render` only walks
  the cells that are inside the viewport.
- `GridModel` (the row renderer's captured `this.model.clone()`) is
  an `Arc<ParsedDocument>` + `Arc<ColumnLayout>` — cloning the model
  for the row closure is cheap.

## Concurrency

### Background work

`MainView::begin_open` and `MainView::choose_entry` both:

1. Bump `generation`.
2. Set `state` to `Loading`.
3. Capture a `cx.background_executor().clone()`.
4. `cx.spawn(async move |this, cx| { ... })`.

The spawned task awaits `executor.spawn(async move {
load_and_index(&path) }).await`, then calls
`this.update(cx, |view, cx| view.apply(outcome, cx))`.

### Task ownership

`MainView.task: Option<Task<()>>`. The latest task handle is stored
in the view; the previous task handle is dropped on assignment, which
cancels it. This is a coarse cancellation: the running `await` on the
background executor is unaffected, but its `update` callback becomes
a no-op because the view entity is dropped... actually no, the entity
is reused. Cancellation is handled by the generation check.

### GPUI task usage

Only `cx.background_executor` and `cx.spawn` are used. No manual
thread pools, no `std::thread`, no `tokio`.

### Cancellation

There is **no** explicit cancellation. Obsolescence is enforced by
the generation counter:

```rust
this.update(cx, |view, cx| {
    if view.generation != generation {
        return; // stale; discard
    }
    view.apply(outcome, cx);
})
```

If the user drops a new file while a large ZIP is still being
extracted + indexed, the in-flight extraction continues to run (we do
not kill it), but its result is silently discarded. The new open's
generation wins.

### Generation IDs

Yes — `MainView.generation: u64`, wrapping on overflow (effectively
never).

### Opening another file while work is in progress

Safe. The state moves to `Loading`, the previous task's eventual
result is dropped at the generation check, and the new task's result
takes over.

### Known limitations

- Dropping an in-flight extraction wastes the CPU/IO already spent on
  it. For very large ZIPs this is observable. A real cancellation
  token would require `zip::ZipArchive` to expose cancellation hooks,
  which it currently does not. Out of scope for Milestone 1.
- There is no progress UI for extraction / indexing. The status bar
  shows a generic `loading — <name>` message.

## Error Handling / Diagnostics

### Typed error surface

`error.rs::AnvilError`:

| Variant                              | Meaning                                    |
|--------------------------------------|--------------------------------------------|
| `Io(io::Error)`                      | Filesystem error during open/extract       |
| `Zip(zip::result::ZipError)`         | Underlying zip crate error                 |
| `UnsupportedCompression(String, String)` | Compression method not Stored/Deflate/Bzip2 |
| `NoUsableEntries`                    | ZIP has no candidate data files            |
| `EntryNotFound(String)`              | Archive entry name not present             |
| `PathTraversal(String)`              | An entry name contained `..`               |
| `DecompressedTooLarge { name, actual, limit }` | Size cap hit                           |
| `EmptyFile`                          | 0-byte input                               |
| `Other(String)`                      | Catch-all                                  |

### User-visible errors

- During open: `MainView::apply` sets `ViewState::Error(message)`,
  which the centre panel renders with a red title and the
  `Display`-formatted error in the middle of the window.
- During archive extraction (entry choice): same path — the result of
  `extract_and_index` flows through `apply`.
- During rendering: `ParseWarning`s are surfaced as a count in the
  status bar, as a sortable list in the diagnostics panel (Cmd/Ctrl+D),
  and as a kind-aware gutter marker on each offending row.

### Logs

- The library uses `eprintln!` nowhere; the binary does so in
  `--probe` and `gen_fixture`. There is no `log` / `tracing`
  dependency today. Diagnostics are collected into `ParseWarning`s
  rather than logged.

### Diagnostics data

`ParseMeta.warnings: Vec<ParseWarning>` carries:

- `InconsistentColumnCount` — row's column count differs from
  expected (header-derived or first-row-derived for headerless files).
- `EmptyHeader` — header cell is whitespace.
- `DuplicateHeader` — header cell already seen.
- `UnterminatedQuote` — file ended while inside a quoted field.
- `VeryLongRecord` — a record longer than `IndexOptions::max_record_bytes`
  (default 1 MiB), including its trailing newline. Emitted by a post
  pass over the finished offset table.

Row warnings are surfaced by the diagnostics panel (Cmd/Ctrl+D) as a
navigable list and by a kind-aware marker (`✖` red for an unterminated
quote, `⚠` warn otherwise) in the row-number gutter;
header warnings are listed but have no row to navigate to. The grid
caches a sorted `(record, WarningKind)` index on `GridModel`, keeping
the most severe kind per row.

## Performance Characteristics

Measured on Apple Silicon (M-series) with the generated fixture set.

### Datasets tested

| Fixture            | Size           | Rows     | Columns | Notes                       |
|--------------------|----------------|----------|---------|-----------------------------|
| `large.csv`        | 173,427,532 B  | 1,000,000 | 20     | mixed strings + numbers + JSON payloads |
| `archive.zip`      | ~52 MB         | same     | same   | deflate; 1 CSV + 4 noise entries |
| `multi.zip`        | 576 B          | 3 + 4    | 3 / 3  | 2 usable CSVs for the picker |
| `malformed.csv`    | 68 B           | 4        | 2/3/4  | quote-not-closed, wrong width, etc. |

### File sizes

- `large.csv` — 165 MiB / 173,427,532 bytes uncompressed.
- `archive.zip` — ~49 MiB compressed (≈28% of the CSV size, expected
  for repetitive payload data).

### Scrolling observations

Not formally frame-timed; the grid rebuilds per frame but only
constructs elements for the visible row range × visible column range
(roughly 30 rows × 6–20 cells). On the 1M-row fixture, scrolling is
visually smooth. `render_row` decodes each record's visible cells in a
single `Cells` pass and copies each cell into exactly one `SharedString`
for the element; it no longer calls `doc.cell` per column (which
re-walked the record from its start, O(columns^2) per row) or allocates
a throwaway `String` plus clone per cell.

### Open-time measurements

`anvil --probe fixtures/large.csv`:

```
file:       large.csv
delimiter:  comma (0x2c)
headers:    true
columns:    20
rows:       1000000
bytes:      173427532
warnings:   0
probe time: 253ms
```

The `measure_large_fixture` test in `tests/core.rs` reports
**~650 MiB/s** indexing throughput on the 165 MiB fixture.

The `measure_filter_large_fixture` test measures a full-column text
filter (`country == US`) over the same 1,000,000-row fixture: **~33 ms**
for 99,479 matches (roughly 10% of rows), well under the Milestone 2
acceptance budget of 2 s.

The `measure_sort_large_fixture` test measures a numeric sort of the
same fixture: **~126 ms** to sort 1,000,000 rows by the inferred-`Float`
`amount` column, well under the Milestone 3 budget of 3 s. The same
test prints the inferred types — `id`/`user_id` = Integer,
`amount`/`risk_score` = Float, `is_verified` = Boolean, the rest Text.

`anvil --probe fixtures/archive.zip` finishes in ~1 s on the same
machine (extract + re-index). The 1 s vs. ~0.25 s delta is the cost
of decompression + temp-file write + mmap.

The `measure_search_large_fixture` test measures a whole-record,
case-insensitive search (the search bar's default) over the 1M-row
fixture. After the 2026-11-10 pass it runs in **~135 ms** (was
**~288 ms**): the fold path now reuses one scratch buffer and a
prebuilt `memchr::memmem::Finder` instead of a naive O(cell × needle)
sliding window, and cells with no uppercase bytes are searched in
place.

The `measure_wide_column_layout` test (500 columns × 300 rows) times
`ColumnLayout::compute`. After the same pass it runs in **~2 ms** (was
**~250 ms**) because the layout decodes each sampled record once
instead of calling `doc.cell` per column.

### Known bottlenecks

- Decompression + temp-file write dominates the ZIP path. Streaming
  directly into the indexer would help, but quoted records need
  random access so the temp file is not avoidable today.
- `render_row` still builds one `SharedString` per visible cell (the
text element owns its bytes), and the case-insensitive highlight path
allocates a case-folded copy per matched cell via `find_ranges`. Both
are bounded to the visible range and were left as-is; an LRU/scratch
reuse would remove them if frame time shows up.
- Text sort builds one owned lowercased key `Vec<u8>` per row (1M
allocations on the fixture). Numeric sort is unaffected. An arena of
key bytes would remove the per-row allocation if needed.
- The indexing loop is a per-byte branch loop. A `memchr`/`memchr3`
skip loop was tried and measured **slower** on the dense fixture
(434 ms vs 250 ms) because there is a delimiter every few bytes, so
the SIMD scan cannot skip and pays per-call setup. Do not "optimise"
it back without a benchmark.

### Unmeasured areas

- Vertical scrolling frame time vs. row count.
- Horizontal scrollbar interaction latency.
- Memory footprint with multiple archives open in sequence
  (`temp_dir` cleanup happens on drop, but we have not measured
  peak RSS).
- Behaviour with non-UTF-8 cell contents (`Cell::as_str` still falls
  back to empty string, but `Cell::is_utf8` and `encoding::scan`
  surface the problem; the GUI does not flag affected columns yet).

## Current Limitations / Technical Debt

### Native Ask model

`src/gliner.rs` is an optional library module behind `nl-gliner`. The Ask
interpreter closure retains its CPU GLiNER2.5 Small model in a mutex; model
loading and inference run on the background executor. Concurrent requests
report busy rather than accumulating inference jobs. The model classifies
the column/operator and extracts a literal value. Confidence, spans, schema,
numeric types, and filter-parser round-trip are checked before preview.
Edits invalidate pending results; tab changes and header reindexing clear
Ask state. Enter refuses partial interpretations or lossy preview syntax.

The `--setup-ask-model` command downloads four files from a pinned revision
into a platform cache (or an explicit model directory). Downloads have
timeouts and size bounds and publish each file atomically. Normal inference
makes no network calls. `--ask-probe <file> <question>` exercises the real
backend without a window. See README and ADR 0002 for setup and limits.

The backend supports one condition and uses conservative guards for common
unsupported requests. Model confidence is not a guarantee of semantic
correctness. Compound extraction, calibrated quality evaluation, GUI download
progress/cancel, independent checksums, hard inference cancellation, and
Windows/Linux verification remain open. The community crate includes unused
CLI dependencies; no Python or separate inference runtime is required.
Default builds exclude this stack. If both features are enabled, GLiNER
takes precedence over the existing generative backend.

### Functional gaps

- Selection (click / shift-click / click-and-drag with edge
  auto-scroll), keyboard navigation (arrow keys, Page Up/Down,
  Home/End for columns, Cmd/Ctrl+Home/End for rows, Tab / Shift-Tab
  between cells, Esc), clipboard copy (Cmd/Ctrl+C, TSV via
  `arboard`),
  search (Cmd/Ctrl+F for the bar, F3 / Shift-F3 for navigation,
  Enter / Shift+Enter inside the bar, Esc to close), and
  multi-document tabs (drop several files, open every ZIP entry as a
  tab, switch / close tabs) plus a left file-manager panel (grouped
  by archive, Cmd/Ctrl+B to toggle) are wired. Keyboard handling
  requires the grid to hold focus; UI regression tests guard the
  focus path, drag-select, auto-scroll, every search-bar transition,
  and the tab lifecycle. `anvil_core::Selection` carries 25 unit
  tests + 14 integration tests; `anvil_core::query::search` carries
  22 unit tests + 8 integration tests; the clipboard formatter and
  cell-count helper are covered end-to-end against real
  `ParsedDocument`s.
- The search bar's UI exposes both `SearchOptions` toggles: an
  `Aa` case-sensitive button and a column-scope chip (header name +
  ×) set by clicking a column header. Clicking the scoped header
  again clears it. Both options are per tab and are mirrored through
  `DocumentSnapshot` like the rest of the search state. Match
  highlighting is gated to the scoped column so a scoped search does
  not light up unrelated columns on a match row.
- The filter and search inputs are real editable fields
  (`ui::text_edit::TextEdit` with caret, selection, mouse click/drag,
  and word movement). The only remaining editing gaps are caret blink
  and in-field horizontal scroll when the text is wider than the field.
- The file panel is fixed on the left and a fixed width; it cannot
  be dragged, moved to the right, or collapsed to an icon rail. It
  shows a flat two-level tree (archive → entry) rather than nested
  directories, and there is no tab reordering. Long labels are
  truncated with an ellipsis but there is no tooltip. Recorded as a
  follow-up.
- Every usable ZIP entry gets a tab eagerly. A ZIP with hundreds of
  entries therefore creates hundreds of (initially unloaded) tabs.
  Lazy loading keeps memory bounded to the tabs the user actually
  visits, but there is no cap or grouping yet.
- Closing a tab does not prompt for unsaved state (there is none yet)
  and does not remember recently-closed tabs.
- Sort, basic type inference, and the column inspector (statistics +
  right-side panel) have landed. Richer type classes (date / datetime /
  UUID / email / URL), caching inferred profiles at open, and scoping
  inspector stats to the filtered/sorted view are outstanding.
- The filter expression language supports `AND` / `OR` and parentheses
  with standard precedence (`FilterExpr` / `parse_expr`), plus the
  row-scope pseudo-columns `any` / `all` (`any empty`, `all notempty`).
  There is no general `NOT` yet, no filter UI for picking a column or
  operator from a menu, and no saved filters. A real column literally
  named `any` or `all` is reachable by `#N`. A quoted value is the
  escape hatch when a value would otherwise collide with a boolean
  keyword.
- The status bar reports a warning count; Cmd/Ctrl+D / the toolbar
  **Diagnostics** button opens a panel that lists each warning and
  jumps the grid to the offending record on click. Richer warning
  types (very-long records) and per-row grid highlighting are
  outstanding. Milestone 4.
- No progress UI for extraction / indexing. Milestone 5.
- No themes, no light mode. Milestone 5.
- UI coverage is now eighty-three UI regression tests (focus, copy,
  drag, auto-scroll, search bar, search options, filter/search text
  editing, filter autocomplete, bar dismissal via Esc and ×, sort,
  column inspector, diagnostics, tab lifecycle) plus the five `rect_contains` /
  `should_highlight` / `warning_kind_for` / `cache_warning_rows` unit tests, three `render_row` smoke tests, the
  eighteen `TextEdit` unit tests, the three `archive_picker`
  display-helper tests, and the twenty-four command-mapping
  unit tests; there is still no automated test of drag/drop event
  delivery or the toolbar. `--probe` remains the only headless
  data-path harness.

### Performance gaps

- `render_row` allocates a `String` per visible cell per redraw.
  Acceptable today; revisit when text shaping / selection arrives.
- No LRU cache for cell text. Repeated scrolling across the same
  rows re-decodes; likely fine but unmeasured.
- ZIP extraction writes the entire entry to a temp file before
  indexing. Streaming would lower peak disk usage; deferred.

### Architectural debt

- `ui::view.rs` was split in the 2026-10-18 iteration. It is down to
  ~2,250 lines (from ~4,800) after extracting `ui::input`,
  `view::search`, `view::filter`, and `view::tests`. It still owns the
  `MainView` state, the multi-document tab list, open orchestration,
  and the toolbar / tab-bar / file-panel / status / grid rendering;
  further extraction (`view::documents`, `view::chrome`) is optional
  and lower priority now.
- `loader.rs::best_candidate` and `ArchiveSource::single_usable`
  duplicate the "one usable entry" question. They agree today;
  consolidate when the loader gains new auto-open rules.
- `parser::mod::Cell<'a>` exposes `into_string` for grid convenience
  but the borrowed path is what the architecture prefers. There is no
  helper that returns `&str` without forcing the consumer to deal
  with `Cow<[u8]>`; clean up when selection arrives.
- `ui::grid::ColumnLayout::compute` measures cell width with a
  hand-rolled `text_width` heuristic. Once GPUI exposes its text
  measurement APIs, switch to those.
- The horizontal scrollbar uses `on_mouse_event` with three handlers
  wired from inside `canvas`. It works but is fragile against GPUI
  API churn.
- No `cargo bench` harness; the only throughput signal is the
  ignored `measure_large_fixture` test.

### Operational debt

- `Cargo.lock` exists; there is no `Cargo.lock` policy documented.
- `fixtures/` is committed and includes a 173 MiB CSV. Useful for CI
  but not great for `git clone` size. Consider generating in CI.
- No CI configuration (`.github/workflows/` etc.). Tests pass locally
  but are not enforced on push.
- Windows, macOS, and Linux are intended target platforms, but this
  repository has only been built and GUI-smoke-tested on macOS so far.
  Cross-platform compilation, clipboard/dialog behavior, and GUI
  backends are not yet verified; Milestone 5 now includes a platform
  matrix and per-OS GUI exercise.

## Architectural Invariants

Concrete rules future agents should preserve unless they intentionally
change architecture and update this file.

1. **`anvil_core` must not depend on `gpui`.** It is the data-side
   crate; the entire test suite depends on this separation.
2. **Never load every cell into independently owned `String`s merely
   for display.** Cell access must go through `ParsedDocument::cell`,
   which returns a `Cell<'a>` borrowing the mmap. Owned strings are
   only justified at the UI boundary (text shaping, clipboard, search
   indexing).
3. **Never perform large dataset scans synchronously on the UI
   thread.** Open, extract, index, search, filter, sort, and column
   statistics all run on `cx.background_executor` and hand results
   back through `cx.update`.
4. **Query logic must not depend directly on rendered GPUI
   components.** `ParsedDocument` and `LoadedDocument` are the
   contract. Search/filter/sort results should be expressed in terms
   of `record_index` and `column_index`, not GPUI element ids.
5. **ZIP-contained files must resolve into the same downstream
   document abstraction as direct files.** `load_entry` returns a
   `LoadedDocument` indistinguishable from one produced for a local
   file. Do not branch on `archive.is_some()` in query code.
6. **Filtering/search results must prefer row references / indexes
   over copies of complete records.** A result row is a `record_index`
   into the `ParsedDocument`; only the cells the UI needs to display
   should be decoded.
7. **Performance claims require measurement.** Every performance
   number in this document, the README, or the agent log must come
   from a `--probe` run or a test, with the dataset name and machine
   implicit in the entry. "Fast" without a number is a documentation
   bug.
8. **Cancellation is via the generation counter, not by killing
   tasks.** Background work that has started may run to completion;
   its result is discarded if `view.generation` has moved on.
9. **Unsafe is centralised.** The only `unsafe` block in the project
   is the `memmap2::Mmap::map` call inside `MmapSource::open`. Any
   new `unsafe` requires justification in a code comment and, if it
   is a durable decision, an ADR.
10. **Temp-file cleanup is implicit.** `OpenedSource.temp_dir`
    owns the `Arc<TempDir>`. Dropping the `OpenedSource` removes the
    temp directory; do not store temp paths separately or skip the
    `Arc<TempDir>`.
11. **The grid owns keyboard focus.** `MainView.focus_handle` is
    attached to the grid via `.track_focus`, and the view focuses it
    when a document is applied and on mouse-down. GPUI only delivers
    key events to the focused path, so dropping `track_focus`
    silently disables every grid shortcut. The UI regression tests
    in `src/ui/view.rs` fail if this regresses.

## Planned Architectural Evolution

The architecture is designed so Milestones 2–5 can be added without
restructuring. Specifically:

- **Natural-language Ask (Tier 1, Tier 1.5, and the opt-in embedded
  model landed; Milestone 6).** The rules-first
  `anvil_core::query::nl` front end emits `FilterExpr` from a phrase,
  reporting unmatched spans and a `clean` flag. Tier 1.5 adds filler
  normalization, fuzzy column matching, `between` ranges, and more
  operator synonyms. It also recognizes row-scope phrasing such as
  `any column is empty`, `at least one column is blank`, `every column
  is filled`, and `no column is empty` (which flips to `all notempty`),
  in either column-first or row-first form (`any row that has an empty
  column`, `rows with no blank cells`), emitting `FilterExpr::AnyColumn`
  / `AllColumn` without touching the per-column value samples. The
  row-first matcher requires an `<empty-word> <column-word>` ending so
  ordinary `rows with amount over 100` still falls through. `Cmd/Ctrl+Shift+L` opens the Ask bar
  (`ui/view/ask.rs`), which previews the parse and accepts it into the
  normal filter bar; `Ctrl/Cmd+Enter` escalates an unresolved phrase to
  the optional backend. The embedded backend (`src/nlmodel.rs`, behind
  the off-by-default `nl-model` feature) loads a quantized instruct
  model via candle and is validated by `validate_candidate`, so no
  backend can produce an arbitrary query. A general `FilterExpr::Not`
  remains outstanding; row scope landed via `AnyColumn` / `AllColumn`.
  See `docs/adr/0001-natural-language-ask.md`.
- **Multi-document / tabs (landed).** The tab strip and the
  left-hand file panel are the first consumed step of the "multiple
  datasets" idea in the roadmap's Future Ideas. Every usable ZIP
  entry becomes a tab up front and extracts on demand, so the strip
  and panel list archives without paying to load them all. A future
  dockable panel (right side, draggable width) or a truly nested
  tree (directories inside archives) can reuse the same
  `DocumentSnapshot` list and `group_documents` grouping; only the
  presentation changes. Tab reordering, recently-closed tabs, and
  remembering per-document state across app restarts are all
  extensions of the current model rather than rewrites.
- **Selection / navigation / clipboard (Milestone 2, partial).**
  `Selection` (in `anvil_core::selection`) lives on `MainView` and
  stores `(record_index, column_index)` ranges, independent of GPUI
  elements. Keyboard handling routes through `commands::action_for`
  in `ui/commands.rs`; `MainView::run_action` executes each decoded
  `Action` against view state. Clipboard copy is implemented:
  `Selection::copy_text_with` renders TSV;
  `MainView::copy_selection_to_clipboard` writes through the
  injectable `ClipboardWriter` (default `arboard`);
  `MainView::status_message` shows "copied N cells" in the status
  bar; the copied cells flash `BG_COPIED` for 450 ms. The grid
  tracks `MainView.focus_handle` so keyboard events reach
  `on_grid_key_down`; drag-select is wired via per-cell
  `on_mouse_move` plus an overlay-canvas global listener and tick
  loop for edge auto-scroll. UI tests guard all of it. Cmd/Ctrl+Home/End
  and Tab / Shift-Tab are wired and tested as of the keyboard-nav
  slice.
- **Search (Milestone 2).** `query::search` (in
  `anvil_core::query`) owns the streaming search:
  `pub fn search(doc: &ParsedDocument, needle: &str, opts:
  &SearchOptions) -> Vec<u64>` returns the matching record indexes in
  record order, walking each record's bytes through `Cells::new`
  (which handles quoting / escapes) and matching with
  `memchr::memmem::Finder`. Case-insensitive matching is the default
  and uses ASCII lowercasing on the needle and on a sliding window
  of the cell. `SearchOptions { case_sensitive, column, max_matches }`
  carries the toggle / scope / cap. `MainView` owns
  `search_open / search_query / search_matches / search_active /
  search_generation / search_case_sensitive / search_column /
  search_task / search_focus_handle / focus_search_on_next_frame`,
  mirrored per tab on `DocumentSnapshot`. `MainView::search_options()`
  is the single source of truth for the options, used by both the
  background search and the grid highlight pass so they cannot
drift. Cmd/Ctrl+F opens the bar (the grid's
  `Action::OpenSearch` arm); every typed character spawns a
  background `cx.spawn` task that runs `query::search`; the task
  carries the generation so obsolete runs are discarded by an
  `if view.search_generation != generation` check on `update`.
  Enter / Shift+Enter inside the bar cycle matches;
  F3 / Shift-F3 cycle matches from anywhere via `Action::NextMatch`.
  Each match jump sets the selection cursor and calls
  `scroll_to_item_strict(.., ScrollStrategy::Top)` so the matched row
  is visible. Match rows are tinted `BG_MATCH`; the active row uses
  the stronger `BG_MATCH_ACTIVE`; the literal matched substring
  inside each cell is drawn with a brighter `BG_MATCH_TEXT`
  background so the user can see *where* in the row the match is.
  The byte ranges come from `anvil_core::find_ranges`, called per
  visible cell of a match row. The bar's focus handle is
  independent of the grid's, so typed characters route through
  `on_search_key_down` rather than moving the cursor. Cmd/Ctrl+F is
  a no-op when the bar is already open; when the *filter* bar is open
  (and focused, or with focus on the grid) it switches to search,
  closing the filter bar first. Cmd/Ctrl+L performs the symmetric
  switch from search to filter via `MainView::switch_to_search` /
  `switch_to_filter`, which also clear a stale grid-focus request so the
  destination bar receives focus. The bar sits as a
  normal-flow child of the center flex container (not absolute), so
  when it is open the grid (and its sticky column header) shifts
  down by the bar's height rather than sliding under it; this keeps
  the active-match highlight fully visible even when the match is at
  row 0. The bar also exposes an `Aa` case-sensitive toggle and a
  column-scope chip; **Alt/Option-clicking** a `grid::render_header`
  cell toggles `search_column` (clicking the scoped header again
  clears it) and the scoped header is painted `BG_MATCH_ACTIVE` even
  while the bar is closed. `grid::render_row` highlights only the
  scoped column via `should_highlight`.
  `MainView::jump_to_active_match` keeps the active match on screen on
  both axes: `display_position` maps the record through `view_rows`
  (the filtered/sorted order) before `v_scroll.scroll_to_item_strict`,
  and `ensure_column_visible` adjusts `scroll_x` so the matching column
  — the scoped column, or `first_match_column`'s first hit for a
  whole-record search — is fully inside the viewport. The same
  `ensure_column_visible` runs after arrow / Tab navigation so the
  cursor never walks off the edge. UI regression tests cover the
  open/close cycle, character append, Backspace, Enter cycling, F3
  cycling, the generation guard, the `Aa` toggle, column scoping,
  header-click toggling (through a test debug selector on header
  cells), and horizontal scroll-into-view for a far-right match.
- **Filter (Milestone 2, landed; compound predicates Milestone 4).**
  `query::filter` (in `src/query/filter.rs`) owns the predicate model.
  `FilterOp` covers `==`, `!=`, `contains`, `!contains`, `startswith`,
  `endswith`, `empty`, `notempty`, and the numeric orderings `>`, `>=`,
  `<`, `<=`. The pseudo-columns `any` / `all` (`FilterExpr::AnyColumn`
  / `AllColumn`) scope a predicate across every column, so `any empty`
  matches a row with at least one blank cell and `all notempty`
  requires every cell; evaluation reuses one prepared predicate and the
  `Cell` borrow, short-circuiting on the first match / mismatch.
  `parse` turns a one-line single predicate (`<column> <op>
  [value]`, where column is a header name, a 0-based index, or `#N`)
  into a `Filter`. `FilterExpr` is an AND/OR tree: `parse_expr` is a
  recursive-descent parser over a small tokenizer (`(`, `)`, unquoted
  case-insensitive `AND`/`OR`, and words; quoted values may contain
  keywords), with AND binding tighter than OR. `apply` evaluates a
  slice of filters (AND) over the `ParsedDocument` and returns the
  matching record indexes in order; `apply_expr` evaluates any tree by
  preparing each predicate once and short-circuiting per row; both
  return the matching record indexes in order;
  text operators fold ASCII case, ordering operators skip non-numeric
  and missing cells, and a missing cell counts as empty. The UI keeps
  `filter_input` / `filter_applied` / `filter_rows` / `filter_generation`
  per tab (mirrored into the active document) and runs `apply` on the
  background executor with generation-based obsolescence. The grid
  maps each display position through `filter_rows` to a record index,
  so the row renderer, selection, and search highlighting all keep
  working on record indexes unchanged. `move_selection` walks the
  visible rows so arrow keys never land on a hidden record. The
  status bar shows `N rows (filtered from M)`.
  Autocomplete (`query::suggest` + `ui/view/filter.rs`) computes the
  grammar slot at the caret with a lenient state machine (never fails
  on incomplete input) and offers the row-scope pseudo-columns
  `any` / `all`, columns, operator spellings,
  `AND`/`OR`, and bounded sampled values for the value slot. The popup
  is an overlay (rendered through `render_overlay` so it paints above
  the grid); Up/Down move the selection, Enter/Tab or a click accept
  (replacing the partial token via `TextEdit::replace_range` and
  appending a separator when needed), and Esc closes the popup before
  the bar. The popup tracks a `ScrollHandle` (`filter_suggestion_scroll`)
  and calls `scroll_to_item` on every selection change, so the
  highlighted row is kept in view once the list overflows the 200px
  popup. Value samples come from `schema::stats::sample_distinct`
  (up to 50,000 samples spread evenly across the whole file, at most
  1000 distinct values; ~16 ms once per column on the 1M-row fixture),
  cached per column in `filter_value_cache` and cleared when the active
  document changes. Spreading the sample across the file matters for a
  sorted column, where a rare value first appears far past the head.
  Column labels round-trip through the parser: `resolve_column` checks
  an exact header match first (so a column named `42`, `col0`, or even
  `#2` resolves to itself) before falling back to `#N`/`colN`/numeric
  index, and a multi-word column name is inserted quoted so it stays one
  token. Value matching is ranked (whole prefix > word prefix >
  substring), so typing a later word of a multi-word value still
  surfaces it.
- **Sort (Milestone 3, landed).** `anvil_core::query::sort::apply`
  returns a stable `Vec<u64>` permutation of the supplied view.
  `MainView` keeps a per-tab `sort_spec` / `sort_rows`; a plain header
  click cycles none → ascending → descending → none and a background
  task recomputes the permutation (guarded by `sort_generation`). The
  comparator kind comes from `schema::infer`, empties sort last, and
  the base is the filtered set so sort composes with filter.
- **Type inference and statistics (Milestone 3).**
  `anvil_core::schema::infer` samples each column (bounded to 2048
  rows) and returns `ColumnProfile { name, column_type, non_empty,
  numeric_fraction, .. }`. `schema::stats` builds a full `ColumnStats`
  per column. Both currently run inside the tasks that need them (sort
  and inspector); caching the profiles on the document at open, and
  adding date/UUID/email/URL classification, remain optional
  follow-ups.
- **Column inspector (Milestone 3, landed).** A right-side
  `flex_shrink_0` panel (`theme::INSPECTOR_WIDTH`) sits beside the
  grid body. `Cmd/Ctrl+I` and the toolbar **Inspector** button toggle
  it; `MainView::kick_inspector` runs `column_stats` on the background
  executor, guarded by `inspector_generation`, and rescans only when
  the selected column changes (so vertical navigation is free). It
  follows the selection and reports exact vs approximate distinct,
  min/max, longest/shortest, samples, and frequent values. The grid's
  synchronously-computed viewport means the panel narrows the grid in
  the same frame it opens, with no scroll-math changes. Stats scan the
  whole document, not the
  filtered/sorted view (a follow-up).
- **Diagnostics (Milestone 4, landed).** A right-side
  `flex_shrink_0` panel (`theme::DIAGNOSTICS_WIDTH`) lists the active
  document's immutable `ParseMeta.warnings`; Cmd/Ctrl+D and the
  toolbar **Diagnostics** button toggle it. Warnings need no
  background work; the panel also kicks an `encoding::scan` on the
  background executor when it opens (generation-guarded, cached until
  the document changes) and shows a BOM notice and per-column
  non-UTF-8 counts. Clicking a row warning moves the selection to that
  record and
  scrolls the (possibly sorted) display order to it; a record hidden
  by the active filter is not navigated to (that would silently land
  on an unrelated row) and instead reports in the status bar.
  Header-level warnings (`record_index == None`) and encoding findings
  are listed but not navigable. Offending rows are flagged in the grid
  by a
  kind-aware marker (`✖` red for an unterminated quote, `⚠` warn
  otherwise) in the row-number gutter (`RowContext::warning_rows`,
  a sorted slice the row renderer binary-searches). Earlier
  iterations
  also fixed the `UnterminatedQuote` warning's `record_index`, which
  previously pointed one row too early whenever an earlier row had
  completed, and added `VeryLongRecord` emission (any record over
  1 MiB).
- **Additional archive formats (Future).** The
  `DataSource` / `OpenedSource` abstraction is format-agnostic. A
  future `source::gzip` or `source::tar` can sit alongside
  `source::archive` and feed the same parser. Magic-byte sniffing in
  `open_path` is the only dispatch point that needs updating.
